# WSLAB — Wall Street Lab
### Design Document v1.0

> A TUI backtesting and Bayesian optimization engine for stock market strategies. Portfolio project. Not intended for live trading.

---

## 1. Overview

WSLAB is a terminal-based application for algorithmic trading strategy development. The user loads a strategy, points it at a ticker and date range, runs a backtest, optionally runs Bayesian optimization to find better parameters, and views results — all without leaving the terminal.

The UI is built with **Textual** (Python). The backtesting engine uses **`backtesting.py`** under the hood, with data fetched via **`yfinance`**. Optimization is handled by **`scikit-optimize`** (Bayesian/GP-based).

---

## 2. Core Features

### 2.1 Backtesting
- User selects a ticker (e.g. `AAPL`, `SPY`) and a date range
- User selects a strategy from the available built-in strategies, or loads a custom one
- Backtest runs and returns key metrics
- Results are displayed in the TUI
- An HTML chart is exported (via `backtesting.py`'s built-in plotting) and opened in browser on demand

### 2.2 Bayesian Optimization
- User selects which strategy parameters to optimize and their search ranges
- WSLAB runs multiple backtest iterations using Gaussian Process optimization (`scikit-optimize`) to find the parameter combination maximizing a chosen metric (default: Sharpe Ratio)
- Results show the best found parameters and corresponding performance metrics
- User can immediately run a backtest with the best parameters

### 2.3 Custom Strategies
- Users define strategies as Python classes inheriting from `backtesting.Strategy`
- They implement two methods: `longSignal()` → returns bool, `shortSignal()` → returns bool
- WSLAB wraps these into the `backtesting.py` `next()` loop automatically, so users don't need to touch trade logic
- Custom strategy files can be dropped into a `/strategies` folder and auto-discovered at startup

### 2.4 Charting
- After a backtest, user can open the interactive HTML chart in their default browser
- Chart is generated by `backtesting.py`'s built-in `plot()` method
- WSLAB just handles the trigger and file management

## 3. Built-in Example Strategies

Two strategies ship out of the box, primarily to demonstrate the `longSignal`/`shortSignal` interface:

### SMA/EMA Crossover
- Parameters: `fast_period` (default 10), `slow_period` (default 30), `ma_type` (SMA or EMA)
- Long signal: fast MA crosses above slow MA
- Short signal: fast MA crosses below slow MA

### MACD
- Parameters: `fast` (default 12), `slow` (default 26), `signal` (default 9)
- Long signal: MACD line crosses above signal line
- Short signal: MACD line crosses below signal line

Both use `ta-lib` or `pandas-ta` for indicator calculation (whichever is easier to install cross-platform — prefer `pandas-ta`).

## 4. TUI Layout (Textual)

The app is a single-screen Textual app with a sidebar + main area layout. Navigation between sections is done via a sidebar or tab bar. No multi-window complexity.

### Screens / Sections

```
┌─────────────────────────────────────────────────────┐
│  WSLAB — Wall Street Lab                  [Q] Quit  │
├──────────────┬──────────────────────────────────────┤
│              │                                      │
│  [Backtest]  │   Main content area                  │
│  [Optimize]  │   (context-sensitive)                │
│  [Results]   │                                      │
│  [Strategies]│                                      │
│              │                                      │
└──────────────┴──────────────────────────────────────┘
```

**Backtest Panel**
- Ticker input
- Date range inputs (start / end)
- Strategy selector (dropdown of discovered strategies)
- Strategy parameter inputs (dynamically generated based on selected strategy)
- Cash / commission inputs
- [Run Backtest] button

**Optimize Panel**
- Same ticker / date range / strategy selector as Backtest
- For each optimizable parameter: range inputs (min, max, step)
- Metric to optimize (Sharpe Ratio, Return %, Max Drawdown — selector)
- Number of optimization iterations (default: 50)
- [Run Optimization] button
- Progress bar during optimization

**Results Panel**
- Displayed after a backtest or optimization run
- Key metrics table: Return %, Sharpe Ratio, Max Drawdown, Win Rate, # Trades, Profit Factor
- If optimization: best parameters found, displayed clearly
- [Open Chart] button → opens HTML chart in browser
- [Run with Best Params] button (optimization only)

**Strategies Panel**
- Lists all discovered strategies (built-in + custom)
- Shows strategy name, description (from docstring), and parameter list
- Instructions for adding a custom strategy

## 5. Strategy Interface

Custom strategies must follow this interface:

```python
from wslab.strategy import WSlabStrategy

class MyStrategy(WSlabStrategy):
    # Define optimizable parameters as class attributes
    fast_period = 10
    slow_period = 30

    def longSignal(self) -> bool:
        """Return True to go long."""
        ...

    def shortSignal(self) -> bool:
        """Return True to go short (or close long)."""
        ...
```

WSLAB's base class handles:
- Calling `longSignal()` and `shortSignal()` each bar in `next()`
- Managing position state (no double-entry, no entry without close)
- Passing data (`self.data`, `self.I()`) through to the subclass normally

Parameters defined as class attributes are automatically surfaced in the TUI and flagged as optimizable.

## 7. Project Setup

### `setup.sh`
The repo ships with a setup script that:
1. Creates a virtual environment (`venv/`)
2. Installs all dependencies from `requirements.txt`

Run with:
```bash
chmod +x setup.sh && ./setup.sh
```

Then launch with:
```bash
venv/bin/python src/main.py
```

### Manual setup
Just replicate what the script does. You can figure it out.

## 9. UX Notes

- Dark theme. Textual's default dark theme is fine; no need to over-customize.
- Keyboard-first. All major actions should be triggerable by keyboard shortcuts, not just mouse clicks.
- Errors should be shown inline (not as popups if avoidable). Failed backtests, bad tickers, invalid date ranges — surface clearly in the results area.
- The optimization progress bar is important UX — Bayesian opt with 50 iterations on slow tickers can take a while.
- Keep the TUI lean. Don't try to replicate the HTML chart inside the terminal. The chart opens in a browser; the TUI shows numbers.
